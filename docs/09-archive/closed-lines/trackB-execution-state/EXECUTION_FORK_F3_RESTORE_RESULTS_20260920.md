## 结果

### E6 Restore Depth:**指标 2 通过**(链 A@8K→B@16K→C@24K→D@32K,段表 v2 支持多级 fork)

| 恢复路径 | 机制 | 16K / 24K / 32K 实测 | 形状 |
|---|---|---|---|
| R1 全量磁盘往返(生产 v1 同型) | 整视图 safetensors save→load→重建 | 6.3 / 10.7 / 8.6 ms(单层;本机 SSD 快,生产 18.2s@120K 为多层全模型) | ∝ 总深度(线性,基线复现) |
| **R2 页恢复(共享驻留)** | 只落盘/回读本级私有页 + 重挂段表 | **6.4 / 7.7 / 7.5 ms(每级私有 8K 行=16MiB 恒定)** | **平坦(1.22)→ 亚线性 ✓** |
| R3 重放恢复 | 浅锚点 re-fork + 重放 gap | 8K 锚:1542ms / 16K 锚:1020ms / 24K 锚:512ms | ∝ gap(检查点粒度=恢复上限) |
| GDN 态恢复 | 固定尺寸两数组往返 | 0.8 ms 恒定 | O(1),深度无关 |

- R2 恢复正确性:B/C/D 三级恢复后终视图 == 活体终视图**逐元素相等**;
  三点数据(16K/24K/32K,平坦度 1.22)主张范围为**本次测量区间**,
  任意深度的复杂度主张留待 F4-A 扩深(65K/131K)与重复次数(×3)
  压测;
- 段表 v2:**COW→COW 多级 fork 成立**——fork O(1)(复制段表),安全
  性 = append-only 缓冲上行区间不相交 + 增长拼接换新缓冲不回写。
  这同时把报告开放问题 2(Page 粒度:层内分页 vs 层间快照)的答案
  推进为:**段表(层间快照链)可行为原型,粒度=段(每级 fork 点)**;
- 计时口径注意:R2 的"恢复"=私有页 I/O + 重挂,不含全视图物化
  (物化是消费侧成本,在首次 attention 时支付)。

## 决策

1. **报告 §5.1 四项验收指标探针级全部闭合**:
   ①Fork Cost 0.019–0.061ms ✓;②**Restore Depth 亚线性(1.22 平坦度)**✓;
   ③Shared Ratio 0.889–0.97 + 精确 1.00× 增长 ✓;④逐 token 一致
   16/16 + 32/32 ✓。**Track B 无止损触发,原型假设全部成立。**
2. **F3a 降级为回归测试项**(非删除):模型级 decode 税 1.01× 仅为本
   工作负载观测;后续每次模型级实验附带 fork-vs-fresh 计时,税比
   >1.10× 回涨即重新激活专门消解。
3. **F4 方向(从探针走向工程)**:
   a. 与 #1849 合流评估:段表 v2 的对外接口(storage 可替换性)对齐
      上游 hooks 提案;
   b. 长深度(≥65K)+ 多会话并存的模型级压测(当前最深模型级 4.2K);
   c. ExecutionState 统一抽象成文:cache 段表 + GDN 引用 + LMOutput.State
      (F2 已证 state 线程化)+ fork/restore/branch 语义清单
      ——即 F0 上游草案的升级版素材;
   d. 上游 fork 远端(slamfinger/mlx-swift-lm)建立,实验分支备份。
4. **环境教训入档**:连续重型测试(20GB 级模型加载)之间必须检查
   内存健康——本轮曾因前次运行的 swap 残留(20GB)导致后续进程页错误
   风暴,全量降速 33–1000×(GPU 等待/换页),数字作废重测方得真值。
   **重跑前查 `vm_stat` 空闲页与 `sysctl vm.swapusage`;重型 suite 单独
   进程跑,不与其它 suite 合并。**
