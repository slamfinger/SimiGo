# 重连计数器 × 重渲时长死循环：心跳防不住的总时长型重连（2026-09-18 晨）

**日期：** 2026-09-18 06:43–07:14
**会话：** 442fbf/main（90k 上下文，qwen3.5 混合架构）
**定性：** 新型死循环——既有两类死循环（毒 session 生命周期 / 重建×超时）之后的第三形态
**终止：** 用户手动停止客户端（否则按 10 次重连上限还有 ~70 分钟纯损耗）

## 现象

客户端 UI「重新连接中... 3/10」。引擎侧每一次重连对应一轮
`CANCEL → 新 REGISTER → 90,204 tok 从零全量重渲 → 客户端 ~10.5 分钟放弃`：

```text
06:43 第1次  253→171→50 tok/s 递减      → 06:54:03 CANCEL（~70k 进度丢弃）
06:54 第2次  从零再渲，衰减更快          → 07:05:08 CANCEL（~70k 丢弃）
07:05 第3次  58s→82s→174s→174s（17k/段）→ 07:14:52 CANCEL（用户手动终止）
```

三次 ≈30 分钟 GPU 纯损耗，交付 token = 0。swap 5.5→7.5GB 逐轮恶化，
衰减随之加速（第 1 次 68k 处 50 tok/s；第 3 次 68k 处已 99 tok/s 起步后继续掉）。

## 机制：三个环节相乘

```text
客户端重连策略（总时长 ~10.5 min 触发，与静默无关）
× GDN 分歧税（90k 上下文全量重渲 ≈ 16 min @ 50-170 tok/s）
× 引擎缓存事务语义（cancel → 部分预填全部作废，retry 从 0）
= 每迭代一次、交付为零、且机器更慢的自持循环
```

10 次重连上限意味着不做干预的最坏路径：~70 分钟逐次恶化直到客户端彻底放弃。

## 与既有形态的区分

| 形态 | 根因 | 破局点 |
|---|---|---|
| 毒 session 挂死（09-17 晚） | 生命周期：被取消的新 session 留池可复用 | poisonedSessionEvict（已修） |
| 重建×超时（09-17 深夜） | 单次分歧税 > 客户端超时，重试不重置 | suspend/换 payload；容量治理 |
| **本形态（09-18 晨）** | **重连计数器把「放弃并重试」自动化**，每轮重置引擎进度但重置不了机器内存状态 | **客户端停止重试**（本次实际破局）|

引擎全程行为正确：CANCEL→RELEASED 干净、无孤儿、poisonedSessionEvict 零误触发、
admission 行每轮语义正确（单会话 90k ≤ 预算且为当前会话，无可逐对象）。

## 关键疑点（待查，入 5.1 议程）

**SSE 心跳未能阻止重连。** 心跳（startSSEHeartbeat）设计目标是覆盖
「静默预填窗口零出站字节」——但本轮客户端仍按 ~10.5 分钟节奏重连。
两个候选：客户端重连判据是**总时长**而非静默时长（心跳保活无效）；
或该请求路径心跳未生效（需 Protocol 层日志佐证，native_mlx_trace
看不到 SSE 层）。本形态与心跳修复（记忆 SSE-heartbeat 条目）的关系
必须在 5.1 评审前查清。
