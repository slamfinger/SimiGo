# 工程经验

这里记录 SimiGo 开发过程中真实发生的故障、踩坑、回归和经验。

## 定位

工程经验不是架构铁律。

一条经验应回答：

- 发生了什么？
- 为什么发生？
- 哪些尝试失败了？
- 最终如何处理？
- 这个结论适用到什么范围？
- 是否值得进一步验证或升级为架构决策？

## 晋升路径

```text
问题 / 故障
    ↓
Lesson
    ↓
Test / Experiment
    ↓
Benchmark / Evidence
    ↓
ADR
    ↓
必要时才进入 Core Invariant
```

不要因为一次 Bug 就增加一条核心规则。

## 文档要求

每篇经验尽量包含：

```text
背景
现象
证据
根因
处理方式
失败方案
影响范围
长期结论
是否需要 ADR
```
