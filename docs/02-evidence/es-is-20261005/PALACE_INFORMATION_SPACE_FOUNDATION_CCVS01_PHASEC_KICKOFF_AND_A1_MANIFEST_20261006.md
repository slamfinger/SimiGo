
### 2.1 Seam map

```text
process/socket boundaries: NONE — single process, in-process library calls
                           (this is the topology property under test).
```

### 2.2 Durable acknowledgement points

```text
entity write      = file written + fsync + digest re-read match.
registry write    = SQLite COMMIT (WAL mode, synchronous=FULL).
session append    = SQLite COMMIT.
availability      = SQLite COMMIT.
search upsert     = same transaction as the registry record it mirrors;
                    FTS5 table committed with the registry transaction.
```

### 2.3 Transaction / serialization boundaries

```text
transaction boundary = one SQLite transaction per logical operation
                       (produce = entity write then registry transaction;
                       crash between them is an F1 exposure by design).
serialization        = single-writer discipline via SQLite locking; readers
                       use WAL snapshots.
```

### 2.4 Semantic continuity rules

```text
representation-to-registry consistency:
  registry row for a representation is committed only after the entity file
  is durable; digest stored in registry must equal file digest.

locator update rule:
  MOVE/RENAME inserts a new locator record and retires the old one in the
  same transaction; InformationID and RevisionID unchanged (I1).

historical pin rule:
  pin stores (informationID, revisionID, representationID, locator, digest,
  observedAt); pin resolution returns exactly the pinned tuple (I6).

availability/tombstone rule:
  DELETE appends a `deleted` availability record; representation file and
  registry rows remain (I7). RESTORE appends `restored`; the deletion
  observation remains in history (I8).

identity rule:
  InformationID is an opaque UUID generated by the adapter at create time;
  paths are locator data only; same path + different digest never reuses an
  identity (I3); same digest at a new path creates a NEW InformationID
  unless an explicit copy-of relation is recorded (I4).
```

### 2.5 Index rebuild source

```text
rebuild source = registry authority tables (representations + revisions +
                 locator current view); FTS5 is derived only (I11).
```

### 2.6 Crash recovery boundary

```text
crash model    = process kill (SIGKILL) at F1–F9 per frozen protocol.
recovery       = SQLite WAL recovery on reopen; entity/orphan reconciliation
                 via integrity report (digest + registry cross-check);
                 repair writes an explicit repair record (REPAIR class).
power-loss durability is out of scope (ruling R6).
```

### 2.7 Backup / restore boundary

```text
backup   = SQLite backup API (consistent snapshot) + entity directory copy.
restore  = restore both, then full integrity report must pass.
smoke-level test required by G8.
```
