## 2. PB-F2 — Frozen fixtures (deterministic synthetic generation)

All fixtures are synthetic. No real user data, credential, or private secret
may enter a fixture. Fixture content stays inside the registered UTF-8 /
text-bounded PRQ-ISF-01 domain.

Frozen fixture rules:

```text
Master seed            = 20261006; every run records the seed actually used.
Seed derivation        = one child seed per workload family, derived from the
                         master seed with a declared, recorded formula.
Content generator      = deterministic UTF-8 text generator; identical inputs
                         must yield byte-identical fixtures.
Small entity sizes     = uniform in [1 KiB, 64 KiB].
Medium entity sizes    = uniform in [64 KiB, 1 MiB].
Large entity size      = exactly 10 MiB each.
Relation graph         = generated with declared average out-degree 2,
                         including explicit split and merge lineage segments.
Session stream         = strictly ordered events, monotonic logical
                         timestamps, one summary record per 100 events.
Identity semantics     = paths, names, and digests are generated by the
                         fixture generator; identity continuity is asserted by
                         invariants I1–I13, never assumed from naming.
```

The fixture generator is part of the frozen benchmark harness. Its version and
content hash are recorded in every run config.

## 3. PB-F3 — Frozen evaluation bounds and correctness gates

### 3.1 Binding workload

```text
Binding workload = WL6 mixed research day.
Secondary binding metrics = WL1 small-object P95, WL3 session append P95,
                            WL4 relation insert / 2-hop P95, WL5 search P95.
All bound checks are evaluated on the MEDIUM tier, cold mode.
```

Binding-role discipline (ruling R3):

```text
WL6      = primary architecture binding workload.
WL1..WL7 = mandatory diagnostic / capability evidence, each reported
           independently under its own family results.
WL6 PASS never implies large-file, relation-heavy, search-rebuild, or
fault-recovery PASS. A decisive advantage confined to one diagnostic family
is reportable evidence and may drive Phase D discussion.
```

### 3.2 Correctness bounds (hard, unchangeable)

Hard eligibility gates are frozen exactly as Phase A §8.1 (G1–G8):

```text
Consistency invariants I1–I13 = all pass.
Crash points F1–F9            = PASS / REPAIR / DETACHED only; FAIL forbidden.
Historical pin                = must resolve to exact prior representation.
Index rebuild                 = must derive an equivalent view from authority.
```

A correctness failure is a protocol failure of the candidate, not a reason to
relax a bound.

### 3.3 Performance bounds (frozen evaluation bounds, ruling R1)

A composition "meets the Phase B performance bounds" — the condition used by
the Phase A §8.3 anti-complexity rule — if and only if all of the following
hold on MEDIUM, cold mode, valid runs only:

| # | Metric | Bound (P95 unless noted) |
|---|---|---|
| PB-B1 | small-object create | ≤ 25 ms |
| PB-B2 | small-object lookup | ≤ 10 ms |
| PB-B3 | locator move/rename | ≤ 25 ms |
| PB-B4 | revision create | ≤ 50 ms |
| PB-B5 | historical pin read | ≤ 25 ms |
| PB-B6 | session append | ≤ 10 ms |
| PB-B7 | relation insert | ≤ 20 ms |
| PB-B8 | 2-hop traversal | ≤ 100 ms |
| PB-B9 | search query | ≤ 150 ms |
| PB-B10 | WL1 ingest disk amplification | ≤ 3.0 × logical bytes |
| PB-B11 | large-file ingest disk amplification | ≤ 1.2 × logical bytes |
| PB-B12 | MEDIUM full index rebuild | ≤ 10 minutes wall-clock |
| PB-B13 | restart/open after clean shutdown | ≤ 30 s |
| PB-B14 | integrity check (MEDIUM) | ≤ 10 minutes wall-clock |

Bound semantics (ruling R1):

```text
PB-B1..B14 = frozen evaluation bounds observed in the declared fixed
             environment on the declared tier and mode.
PB-B1..B14 ≠ universal engineering guarantees.
           ≠ hard elimination gates by themselves.
```

Baseline-A feasibility / protocol-validity check:

```text
PV1  Baseline A runs first in Phase C.
PV2  For each PB bound, classify after Baseline A's valid MEDIUM runs:
       ACTIVE       = Baseline A median-of-runs result meets the bound.
       UNCALIBRATED = Baseline A systematically misses the bound in the
                      qualified fixed environment.
PV3  An UNCALIBRATED bound triggers protocol/environment validity
     classification. It must not be used to eliminate any candidate; the
     result is recorded as PROTOCOL-VALIDITY-FLAGGED for that bound and
     resolved only by an explicit Human ruling (bound adjustment or bound
     retirement for this environment).
PV4  For a candidate, a miss on an ACTIVE bound is recorded as BOUND-MISS
     evidence. BOUND-MISS does not invalidate a run and does not by itself
     eliminate a candidate; it blocks SHORTLIST-QUALIFIED unless the
     revised anti-complexity rule (§7) justifies the complexity.
```

Rationale: the bounds target interactive research-continuation behavior, not
server-benchmark culture. They separate "the environment cannot support this
bound at all" (protocol validity) from "this architecture misses a bound that
the environment supports" (comparative evidence).

### 3.4 Repetition (frozen)

```text
SMALL  = minimum 5 valid runs
MEDIUM = minimum 5 valid runs
LARGE  = minimum 3 valid runs
STRESS = minimum 1 valid run; 2 preferred
Invalid runs are retained and explained, never silently discarded.
```

### 3.5 Statistical protocol (ruling R4)

Run definition:

```text
One run = one complete topology lifecycle over the declared tier:
          fresh isolated data root + fresh topology processes, executing
          the P0–P9 sequence of Phase A §6.2 once, followed by result export.
Runs are strictly serial; only one registered benchmark runs at a time.
No warm-up runs exist for primary results: every counted run is cold
          (fresh process, fresh data root). Warm data may be reported only
          as supplemental, clearly-labelled diagnostics.
```

Observation minimums per operation type per run:

```text
High-frequency operations (create, lookup, move, session append,
  relation insert): ≥ 500 timed samples per operation per run.
Medium-frequency operations (revise, pin read, availability update,
  1–3 hop traversal, search query, summary read): ≥ 100 samples.
Expensive operations (large-file create/read, startup/open, index rebuild,
  integrity check, crash/recovery probes): every occurrence is an
  observation; no minimum count beyond the workload definition.
```

Aggregation (frozen):

```text
Headline percentile for an operation
  = median of that percentile across all valid runs at the tier.
Pooled across-run values are reported as secondary diagnostics.
PB bound checks and anti-complexity comparisons use headline values only.
```

Percentile validity conditions:

```text
P99 reported only if ≥ 100 pooled samples for that operation at the tier;
  otherwise P99 = NOT-REPORTED (never fabricated or extrapolated).
P95 requires ≥ 20 pooled samples; P50 requires ≥ 10.
```

Run disposition:

```text
A run is INVALID if an invariant fails, the harness errors, required samples
  are missing, or config differs from the declared topology. INVALID runs
  are retained with a required explanation and contribute no samples.
Statistical outliers among valid runs are never discarded; all valid runs
  count. The median-of-runs rule is the declared robustness mechanism.
Attempt budget = 2 × required valid runs per tier. If valid runs cannot be
  achieved within the attempt budget, the candidate's tier result class is
  NOT-COMPARABLE, with the failures documented.
INVALID (protocol/harness/invariant problem) is distinct from FAIL
  (candidate correctness failure under §5 classes).
```

Environment stabilization (frozen):

```text
Before each run: resource gates of §4 must pass; host must be on AC power;
  no pending OS updates; record host load as three consecutive 5 s CPU
  samples with < 20% non-benchmark CPU before the run starts. If the
  quiescence check fails, wait and re-check; record every re-check.
```

## 4. PB-F4 — Frozen resource limits and safety rules

Phase A §7 is frozen verbatim:

```text
Data safety   : benchmark roots outside the Lab working tree; no Lab file
                moved, renamed, deleted, or rewritten; synthetic fixtures only.
Resource gates: free disk >= 3 × declared new bytes; free memory >= 2 ×
                declared max RSS; no other registered benchmark active;
                enough time for timeout + final integrity check. Gate failure
                = RESOURCE_GATE_BLOCKED, never silent tier shrinkage.
Timeouts      : SMALL 15 min / family; MEDIUM 60 min / family; LARGE 4 h /
                family; STRESS 12 h / full sequence. A timeout is a result.
Abort         : free disk < 20%; output unwritable; swap thrashing; any
                protected Lab path touched; unrecoverable integrity violation;
                data loss without a registered recovery rule.
```

Frozen environment declaration: Phase C runs on the registered local
development host. Host CPU, memory, disk type, OS, component versions, and
configuration hashes are recorded before the first run. No cloud or remote
host is in scope for Phase C.

### 4.1 Amplification definitions (ruling R5)

Numerator and denominator are frozen so the metric cannot be gamed by
accounting choices:

```text
Logical payload bytes (denominator basis)
  = sum of fixture entity bytes + session event bytes + relation record
    bytes submitted for durable write during the measured workload window.
  Excludes only harness bookkeeping that is not workload payload.

Physical durable footprint (numerator basis)
  = all bytes written to persistent storage by every topology process in
    the measurement window, counted by OS-level per-process written-bytes
    accounting. Explicitly includes: registry metadata, WAL/journal/redo
    writes, index writes, relation store writes, search index writes,
    persisted temporary files, duplicate or mirrored copies, and
    object-store overhead.
```

Amplification variants:

```text
Steady-state amplification   = primary metric for PB-B10/PB-B11, measured
                               over the ingest/revision workload window,
                               excluding rebuild and recovery windows.
Peak amplification           = max over any 10 s window; diagnostic.
Rebuild amplification        = physical bytes written during index rebuild
                               / logical bytes; diagnostic.
Crash-recovery amplification = physical bytes written during restart/repair
                               / logical bytes; diagnostic.
```

Measurement discipline:

```text
If any topology component's write accounting is unavailable, that
candidate's amplification metrics are NOT-COMPARABLE (never approximated
or estimated).
```

## 5. PB-F5 — Frozen result classes

Run-level classes:

```text
VALID                  = all invariants held; metrics complete; config matched.
INVALID                = retained with a required explanation.
RESOURCE_GATE_BLOCKED  = pre-run gate failed; no run attempted.
TIMEOUT                = declared timeout reached; recorded as a result.
```

Crash-point classes (per F1–F9, frozen from D5):

```text
PASS / REPAIR / DETACHED  = acceptable.
FAIL                      = hard-gate failure (silent identity loss, silent
                            adoption, broken relation, or false history).
```

Candidate-level classes (frozen from D8):

```text
SHORTLIST-QUALIFIED : passes G1–G8 and meets PB-F3 bounds, or justifies added
                      complexity under the §8.3 anti-complexity rule.
CONDITIONAL         : correctness passes but LARGE/STRESS evidence is missing;
                      may proceed only to a targeted test.
ELIMINATED          : fails a hard gate or cannot recover within bounds.
NOT-COMPARABLE      : missing metrics, mid-run topology change, or tier mismatch.
```

No Phase C outcome may be reported as a product endorsement or final database
selection. Phase D ranks qualified architectures only; Phase E is the separate
selection gate.

### 5.1 Crash semantics and claim boundary (ruling R6)

```text
Crash injection for F1–F9 = process-level crash only, implemented as an
unclean kill (SIGKILL) of the topology processes at the declared boundary.
```

Claim boundary:

```text
Passing F1–F9 supports exactly this claim:
  "process-crash recovery validated in the declared environment."

It does NOT support:
  "power-loss durability validated",
  "filesystem-level crash consistency validated", or any stronger claim.

Power-loss and disk-level fault injection are out of scope for Phase C and
require a separate Human commission.
```

## 7. Frozen anti-complexity rule

Phase A §8.3 is frozen with the bound set PB-F3, revised per ruling R2:

```text
Qualification (one of):
  A. End-to-end architecture-level performance gain on the full binding
     workload (WL6, MEDIUM, cold, median-of-runs):
       >= 30% better P95, or >= 50% higher durable throughput,
     measured on the whole candidate composition through the common adapter.
  B. A required capability Baseline A cannot provide without breaking a
     registered boundary, under the same semantic/correctness contract.

Mandatory side conditions (all must hold for either qualification path):
  M1. G1–G8 pass; I1–I13 hold; F1–F9 contain no FAIL.
  M2. No critical resource or recovery regression beyond the frozen
      non-regression line:
        none of {steady-state ingest amplification, total measured RSS,
        startup/open time, restart/recovery time, full index rebuild time}
        exceeds 2 × the Baseline A measured value at the same tier,
        unless a written justification is accepted by Human review.
      An undefined resource or recovery regression is not permitted; every
      regression is either within the line, justified in writing, or it
      blocks qualification.
  M3. Performance gains must be architecture-level and end-to-end.
      Single-component benchmark results are inadmissible as gain evidence.

Otherwise Baseline A remains preferred.
```

## 8. Candidate verdict composition (ruling R7)

No weighted total score exists in this protocol. No rule of the form
`Candidate X > Candidate Y` is computed by summation. The candidate verdict is
layered, and each layer is decided by its own frozen rule:

```text
Correctness   → hard gates G1–G8 with I1–I13 and F1–F9 classes.
Capability    → capability qualification against the registered capability
                list (only declared, manifest-backed capabilities count).
Performance / resource / seam → Pareto and shortlist evidence: headline
                percentiles, throughput, amplification, seam counts, and
                recovery durations are reported side by side as evidence,
                never collapsed into one number.
Anti-complexity → architecture justification per §7.
```

Phase D may rank only SHORTLIST-QUALIFIED architectures, and its ranking is an
evidence-ordered presentation of the layers above, not a score. Final choice
belongs to the Phase E Human selection gate.
