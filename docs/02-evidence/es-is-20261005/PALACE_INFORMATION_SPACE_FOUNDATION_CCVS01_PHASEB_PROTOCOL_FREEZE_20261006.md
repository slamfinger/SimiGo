## 2. PB-F2 — Frozen fixtures (deterministic synthetic generation)

All fixtures are synthetic. No real user data, credential, or private secret
may enter a fixture. Fixture content stays inside the registered UTF-8 /
text-bounded PRQ-ISF-01 domain.

Frozen fixture rules:

```text
Master seed            = 20261006; every run records the seed actually used.
Seed derivation        = one child seed per workload family, derived from the
                         master seed with a declared, recorded formula.
Content generator      = deterministic UTF-8 text generator; identical inputs
                         must yield byte-identical fixtures.
Small entity sizes     = uniform in [1 KiB, 64 KiB].
Medium entity sizes    = uniform in [64 KiB, 1 MiB].
Large entity size      = exactly 10 MiB each.
Relation graph         = generated with declared average out-degree 2,
                         including explicit split and merge lineage segments.
Session stream         = strictly ordered events, monotonic logical
                         timestamps, one summary record per 100 events.
Identity semantics     = paths, names, and digests are generated by the
                         fixture generator; identity continuity is asserted by
                         invariants I1–I13, never assumed from naming.
```

The fixture generator is part of the frozen benchmark harness. Its version and
content hash are recorded in every run config.

## 3. PB-F3 — Frozen success/failure bounds

### 3.1 Binding workload

```text
Binding workload = WL6 mixed research day.
Secondary binding metrics = WL1 small-object P95, WL3 session append P95,
                            WL4 relation insert / 2-hop P95, WL5 search P95.
All bound checks are evaluated on the MEDIUM tier, cold mode.
```

### 3.2 Correctness bounds (hard, unchangeable)

Hard eligibility gates are frozen exactly as Phase A §8.1 (G1–G8):

```text
Consistency invariants I1–I13 = all pass.
Crash points F1–F9            = PASS / REPAIR / DETACHED only; FAIL forbidden.
Historical pin                = must resolve to exact prior representation.
Index rebuild                 = must derive an equivalent view from authority.
```

A correctness failure is a protocol failure of the candidate, not a reason to
relax a bound.

### 3.3 Performance bounds (Phase B bound set)

A composition "meets the Phase B performance bounds" — the condition used by
the Phase A §8.3 anti-complexity rule — if and only if all of the following
hold on MEDIUM, cold mode, valid runs only:

| # | Metric | Bound (P95 unless noted) |
|---|---|---|
| PB-B1 | small-object create | ≤ 25 ms |
| PB-B2 | small-object lookup | ≤ 10 ms |
| PB-B3 | locator move/rename | ≤ 25 ms |
| PB-B4 | revision create | ≤ 50 ms |
| PB-B5 | historical pin read | ≤ 25 ms |
| PB-B6 | session append | ≤ 10 ms |
| PB-B7 | relation insert | ≤ 20 ms |
| PB-B8 | 2-hop traversal | ≤ 100 ms |
| PB-B9 | search query | ≤ 150 ms |
| PB-B10 | WL1 ingest disk amplification | ≤ 3.0 × logical bytes |
| PB-B11 | large-file ingest disk amplification | ≤ 1.2 × logical bytes |
| PB-B12 | MEDIUM full index rebuild | ≤ 10 minutes wall-clock |
| PB-B13 | restart/open after clean shutdown | ≤ 30 s |
| PB-B14 | integrity check (MEDIUM) | ≤ 10 minutes wall-clock |

Rationale: the bounds target interactive research-continuation behavior, not
server-benchmark culture. They are deliberately loose enough that a correct
local composition should clear them, and strict enough that a composed
multi-service topology that pays cross-seam latency on the binding path cannot
hide that cost. A bound failure is recorded as `BOUND-MISS`; it does not
invalidate a run, but it blocks `SHORTLIST-QUALIFIED` unless the anti-complexity
rule justifies the complexity.

### 3.4 Repetition (frozen)

```text
SMALL  = minimum 5 valid runs
MEDIUM = minimum 5 valid runs
LARGE  = minimum 3 valid runs
STRESS = minimum 1 valid run; 2 preferred
Invalid runs are retained and explained, never silently discarded.
```

## 4. PB-F4 — Frozen resource limits and safety rules

Phase A §7 is frozen verbatim:

```text
Data safety   : benchmark roots outside the Lab working tree; no Lab file
                moved, renamed, deleted, or rewritten; synthetic fixtures only.
Resource gates: free disk >= 3 × declared new bytes; free memory >= 2 ×
                declared max RSS; no other registered benchmark active;
                enough time for timeout + final integrity check. Gate failure
                = RESOURCE_GATE_BLOCKED, never silent tier shrinkage.
Timeouts      : SMALL 15 min / family; MEDIUM 60 min / family; LARGE 4 h /
                family; STRESS 12 h / full sequence. A timeout is a result.
Abort         : free disk < 20%; output unwritable; swap thrashing; any
                protected Lab path touched; unrecoverable integrity violation;
                data loss without a registered recovery rule.
```

Frozen environment declaration: Phase C runs on the registered local
development host. Host CPU, memory, disk type, OS, component versions, and
configuration hashes are recorded before the first run. No cloud or remote
host is in scope for Phase C.

## 5. PB-F5 — Frozen result classes

Run-level classes:

```text
VALID                  = all invariants held; metrics complete; config matched.
INVALID                = retained with a required explanation.
RESOURCE_GATE_BLOCKED  = pre-run gate failed; no run attempted.
TIMEOUT                = declared timeout reached; recorded as a result.
```

Crash-point classes (per F1–F9, frozen from D5):

```text
PASS / REPAIR / DETACHED  = acceptable.
FAIL                      = hard-gate failure (silent identity loss, silent
                            adoption, broken relation, or false history).
```

Candidate-level classes (frozen from D8):

```text
SHORTLIST-QUALIFIED : passes G1–G8 and meets PB-F3 bounds, or justifies added
                      complexity under the §8.3 anti-complexity rule.
CONDITIONAL         : correctness passes but LARGE/STRESS evidence is missing;
                      may proceed only to a targeted test.
ELIMINATED          : fails a hard gate or cannot recover within bounds.
NOT-COMPARABLE      : missing metrics, mid-run topology change, or tier mismatch.
```

No Phase C outcome may be reported as a product endorsement or final database
selection. Phase D ranks qualified architectures only; Phase E is the separate
selection gate.

## 7. Frozen anti-complexity rule

Phase A §8.3 is frozen with the bound set PB-F3:

```text
If Baseline A passes G1–G8 and meets PB-F3, a more complex topology may enter
the shortlist only if it demonstrates:
  >= 30% better P95 on the binding workload (WL6), or
  >= 50% higher durable throughput on the binding workload, or
  a required capability Baseline A cannot provide without breaking a
  registered boundary;
and recovery/consistency do not become worse. Otherwise Baseline A is preferred.
```
