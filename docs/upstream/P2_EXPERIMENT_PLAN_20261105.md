## 0. 目标与非目标

**目标**：建立一条**公开可复刻**的证据链，在真实模型上验证 B1 骨架的核心主张——`ES_n ──Settlement──▶ IS ──Admission──▶ ES_{n+1}`，且已结算工作不重执行、续接不依赖旧 KV。

**非目标**：不证明跨引擎/跨载体普适（OQ-7 暂缓）；不修改任何实现；不重复制造历史实验（见 §7）；不宣称语义充分性一般化判据（占位纪律不变）。**证据范围边界（裁定 2026-11-05）**：P2 即使四阶段全部通过，也只支持这条具体参考实现、模型、引擎和配置下的证据链——不自动证明跨引擎普适性，也不关闭 B1 保留的 OPEN 问题。

## 1. 被验证主张 → B1 骨架映射

| 阶段 | 验证的主张 | 对应骨架规则 |
|---|---|---|
| 1 · 真实模型结算 | 结算 fail-closed、恰好一次、结果/来源/版本/依赖可核验 | R1 |
| 2 · 旧 KV 实际释放 | 旧执行上下文的 KV 对续接**不可达**（权威+路径+资源三重） | R4（反面验证） |
| 3 · IS 恢复 | 恢复逐项验证；Settled 与 Recoverable 分离获得直接实验证据 | R2、R6 |
| 4 · 全新 ES 续推 | 新 ES 实例续推真实模型，已结算工作不重新执行 | 骨架闭环、R3 现场 |

## 2. 实验总设

- **被试系统**：当前参考实现（本地 runtime）+ 真实模型（本地引擎）；具体模型与配置属 G1 裁定范围（§8）。
- **证据源四类**：(a) 结构化状态读数（settlements / carrier / dependency 表，只读 SQL）；(b) HTTP 契约终端（typed 拒绝终端、telemetry 块）；(c) 运行时遥测与计账（[EXEC] 行、token 计账、内存读数）；(d) **对抗探针**（显式尝试复用旧 KV、篡改客户端值、违反结算前置条件——探针的"失败"是预期证据）。
- **证据纪律**：每条读数标注来源与采集方式；日志叙述不作为证据（红线延伸）；observed 与 expected 分列入档，非预期读数照实抄写。

## 3. 阶段定义

### 阶段 1 · 真实模型结算

**主张**：模型产生的结果经 ES 权威结算，并具有可核验的结果、来源、版本和依赖信息。

**独立复现步骤（形状；具体命令在真机配置时固定）**：
1. 经公开 HTTP 面发起真实模型生成，构造一个以既有结算为依赖的场景；
2. 只读读取 settlements 行与身份绑定；
3. 对抗探针 A（前置条件违反族）：未 begin 结算 / 换模型结算 / 同 state 二次结算 / 提交未封存依赖地址；
4. 对同一声明集合重复请求。

**可观测证据**：
- E1.1 settlements 行可读：validationStatus、payloadDigest、producer model/tokenizer 绑定；
- **E1.2 探针 A 每项 typed 拒绝，且按写入边界检查（修订 2026-11-05）**：断言 settlements 表无新增**或修改**；对探针可能触及的其他权威状态（身份绑定、依赖边等）按实际写入边界逐项检查；**不把单表行数不变表述为系统全局零写入**。fail-closed 双向验证：拒绝 ⇒ 无相关写入（`SettlementAuthority.swift:5-12`、`AGENT-ACCESS.md:229-240`【已核验】）；
- E1.3 重复请求产生**恰好一次**结算（跨路径恒等；行为断言见 `SimiGoTests/CrossPathSettlementIdentityHTTPTests.swift`）；
- E1.4 digest 重算一致（`payloadDigestMatches`，`SettlementAuthority.swift:62-66`【已核验】）。

**预期读数**：E1.1–E1.4 全部成立。

**反例与失败判据**：拒绝路径出现任何违反预期写入边界的状态变化，包括相关权威状态的新增、修改或删除（具体检查范围按探针实际可能触及的写入边界确定，与 E1.2 一致）；重复请求出现第二结算行；digest 不一致；身份绑定缺失。

**与前后阶段的因果关联**：产出 settlement_id 与 child ES 引用 = 阶段 3 的显式恢复目标、阶段 4 的续接锚；其依赖闭包 = 阶段 3 (iii) 的检查对象与阶段 3 失效注入的靶。

### 阶段 2 · 旧 KV 实际释放

**主张**：旧执行上下文的 KV 在后续续接中**不可达**——不是"逻辑上清空一个引用"。

**"不可达"操作化定义（三重判据，红线 1 的落实）**：
- **O2.1 权威不可达**：该结算未记录 kv 绑定 ⇒ "the continuation has **no authority to reuse KV state**"（`ContinuationAdmission.swift:17-20`【已核验】）；任何显式 reattach 探针 fail-closed 且无状态变化。
- **O2.2 路径不可达（两个独立读数，修订 2026-11-05 P2-R1）**：
  - **O2.2a 寻址面读数**：sessions / branches / checkpoints 等公开寻址面枚举中，不存在可用于恢复旧 KV 的活引用；
  - **O2.2b 消费路径读数（修订 2026-11-05 最终核对：覆盖扩至阶段 3）**：**阶段 3 的 IS Admission / 恢复过程，以及阶段 4 的新 ES 创建与续推期间，未发生旧 KV 或旧 checkpoint 的恢复消费**——覆盖实际可能触发恢复的入口（session 加载、checkpoint 元数据、缓存管理器等），而非只检查一个预期 API。若无法覆盖全部入口，必须明确写出观测范围；**"未观察到"不得升级为"所有路径均不可达"**。
- **O2.3 资源释放读数（直接/间接分级，修订 2026-11-05 P2-R2）**：
  - **直接资源读数**：能归因到 KV 分配或其持有对象的分配量、容量或存活状态（若引擎可提供）；
  - **间接资源读数**：RSS、进程内存等整体指标——仅作**辅助证据**（allocator 保留内存、运行时缓存与模型权重共存时，进程级 RSS 不能归因到 KV；RSS 不下降也不一定说明 KV 仍存活）。
  - 若实际引擎无法提供可归因的 KV 读数，本判据降格标注为**"间接资源证据"**，不得宣称单独证明 KV 已释放。
  - 最终判据：存在**可复核、能支持 KV 生命周期判断**的量化读数——不要求 RSS 必须下降。
  - **合格边界（修订 2026-11-05 最终核对）**：直接资源读数能够支持 KV 生命周期判断时，O2.3 按直接证据判定；若只有间接资源读数，必须标注证据降级，不得将其单独作为 KV 已释放的证明——O2.3 的结论强度受限。**资源读数降级不等于可以降低 O2.1、O2.2 的要求**。

**checkpoint 陷阱（显式处理）**：suspend 语义下"checkpoint 文件是唯一跨 suspend 的存活物"（`BRANCH_FORK_PROTOCOL_DRAFT.md:39-43`【已核验】）。**载体工件物理存在不判失败**；判失败的是**续接路径消费了旧 checkpoint/KV**（如续推读数显示发生 loadSessionCache 式恢复）。旧工件可以存在，但它不得成为阶段 3 / 阶段 4 的恢复来源——恢复来源必须是 IS（这正是被验证的主张本身）。

**独立复现步骤（形状）**：
1. 阶段 1 完成后，触发旧上下文终止——**单一选定条件**：进程退出 / suspend / 新 runtime 实例三者对旧 KV 生命周期与 checkpoint 的影响不同，不得混为同一实验条件；G1 裁定具体选定哪一种，并在证据档案中记录该条件；
2. 采集 O2.1–O2.3；
3. 对抗探针 B：显式尝试经旧句柄恢复（预期 fail-closed——探针"失败"即本阶段证据）。

**预期读数**：O2.1 拒绝且无状态变化；O2.2a 寻址面无活引用；O2.2b 阶段 3 恢复过程与阶段 4 续推的观测范围内均无旧 KV/checkpoint 恢复消费；O2.3 存在可复核、支持 KV 生命周期判断的量化读数（直接读数可判定时按直接证据判定；仅间接读数时标注证据降级，结论强度受限）。

**反例与失败判据**：任何路径（含观测范围内的内部入口）发生旧 KV/旧 checkpoint 恢复消费；reattach 探针"成功"；只有卸载日志而无 O2.1–O2.3 → **判失败（红线 1）**。

**与前后阶段的因果关联**：为阶段 3/4 提供"恢复不依赖旧载体"前提；O2.1 的无 kv 绑定状态与阶段 3 admission 的 kvBindings 语义必须一致（同一结算记录读出）。

### 阶段 3 · IS 恢复

**主张**：从 IS 独立读取已结算结果，来源、完整性、依赖闭包和当前有效性逐项验证；`Settled(ρ)` 与 `Recoverable(ρ, ctx, t)` 的分离获得直接实验证据。

**独立复现步骤（形状）**：
1. 在阶段 2 之后的全新上下文中，以 settlement_id **显式命名**准入（"a consumer that reuses a settled result must name it"，`ISAdmission.swift:128-129`【已核验 2026-11-10】）；
2. 采集准入检查单逐项读数；
3. **失效注入**：对依赖闭包内的来源文件做变更，触发失效传播（注入手段待 G1 裁定——候选：来源文件变更的既有失效机制 `invalidateSourceFile`，`ESISDatabase.swift:6737-6747`【已核验 2026-11-10】）；
4. 在注入后时点 t₂ 再次尝试恢复**同一**结算；
5. 对抗探针 C：篡改客户端提供的续接值。

**可观测证据**：
- E3.1 t₁ 时刻准入逐项读数：digest 完整 / validity='valid' / 依赖闭包逐项 present ∧ valid / 身份绑定 evaluate 结果（`ISAdmission.swift:92-99`【已核验】）；
- **E3.2a 失效传播与拒绝（修订 2026-11-05 P2-R3）**：绑定来源的结算沿闭包翻转 validity='invalid'、**无关结算保持 valid**、无依赖者的变更不产生任何失效（"Unrelated settlements keep validity='valid'. A change with no dependents invalidates nothing."，`ESISDatabase.swift:6733-6747`【已核验 2026-11-10】）；t₂ 对同一结算的恢复被拒且 typed reason 可审计（`Refusal.invalidated` / `dependencyInvalid` 路径，`ISAdmission.swift:146-160`【已核验】）——本读数验证 **R6 分离与依赖类 Refuse**；
- **E3.2b reexec 执行集合（条件读数）**：仅当本轮**实际执行了 reexec**时，记录实际执行集合并与受影响依赖闭包比较，验证 R3 闭包范围。**拒绝与重执行是两个不同事件**（Admission 拒绝不是执行命令）；若实验未实际触发 reexec，**R3 标为"本轮未验证"**——不得因出现 Refuse 而宣称 R3 执行范围已验证。不为本验证强行增加重执行。
- E3.3 探针 C：到达模型的值仍来自权威存储（"the value that reaches the model comes from the authoritative store, not the client"，`ContinuationAdmission.swift:4-7`【已核验】），或请求被拒。

**预期读数**：E3.1 全通过；E3.2a 拒绝 + 传播正确 + 无关结算不受影响；E3.2b 仅在实际触发 reexec 时采集（否则 R3 标"本轮未验证"）；E3.3 篡改无效。

**反例与失败判据**：恢复跳过任何检查项；失效后仍可恢复；客户端篡改值被采纳；无关结算被误伤失效。

**与前后阶段的因果关联**：恢复得到的 (r, ρ, β) = 阶段 4 输入；E3.2a 的依赖类 Refuse 构成 **R3 的触发前提**，但 R3 的执行范围只有 E3.2b（实际执行 reexec 时）才能验证——Refuse 本身不验证 R3；E3.2a 同时是 R6 分离的直接实验化：Settled(ρ) 仍真（记录在、事件发生过），Recoverable(ρ, ctx, t₂) 为假。

### 阶段 4 · 全新 ES 续推

**主张**：新 ES 执行实例消费 β 中经验证的结果与绑定，继续真实模型推理，**已结算工作没有被重新执行**。

**独立复现步骤（形状）**：
1. 阶段 3 恢复成功后，在新 ES 实例上发起真实模型续推；
2. 同步采集"复用 vs 重算"计账；
3. **对照组**：用未结算的等价输入执行一次冷启动生成；
4. 续推完成后结算，读取消费/派生记录。

**可观测证据**：
- **E4.1 复用计账对照（修订 2026-11-05）**：**执行决策计账为主证据**【候选读数：`ManagedContinuation` Committed 的 recomputed / reusedExecution 字段、SettlementConsumption 消费记录指向原 settlement_id——字段名与可读性待真机配置时核验】；**token 计账为辅助证据**（提示长度、输出、tokenizer 行为与生成路径都可能影响读数）。对照组尽可能保持输入、模型、tokenizer 与生成条件一致，并明确区分哪些 token 属于历史已完成工作、哪些属于新续推工作；
- E4.2 无重复结算：已结算工作未产生第二结算行（复用四条件路径，`AGENT-ACCESS.md:102-109`【已核验】）；
- E4.3 引用链可追溯：续推结算产出下一级 child ES 引用，链至少两跳（ES_n → IS → ES_{n+1} → IS → ES_{n+2}；"childESStateID … so the NEXT continuation admits through it"，`ContinuationSettlement.swift:105-106`【已核验】）；
- **E4.4 派生绑定（修订 2026-11-05 P2-R4）**：DERIVED_CONSUMPTION + evaluateConsumer 只能核验**消费关系与消费方身份**；值来源主张需要完整绑定链。证据至少关联五项：
  1. 被恢复的 settlement/result 标识及其 digest；
  2. 消费记录中的来源标识；
  3. 实际消费输入的身份或 digest；
  4. 派生输出的标识或 digest；
  5. 消费方身份验证结果（evaluateConsumer，`ISAdmission.swift:161-169`【已核验】）。

  若现有实现不能提供完整绑定链，E4.4 拆为两级结论——「**消费关系已验证**」与「**具体值派生关系已验证**」，前者**不得当成后者**。【绑定链完整性待真机配置时核验】
  红线 2 的关键：证明已结算结果**实际参与了新计算**，而不只是新 ES 曾经读取过它。

**预期读数**：E4.1 以执行决策计账为主证据、token 计账辅助；E4.2 无重复结算；E4.3 链完整；E4.4 达到绑定链可支持的**最高结论级**并如实标注——若绑定链不完整则如实降级为「消费关系已验证」并在结论中记录该限制（降级不判失败，**冒进升格才判失败**）。

**反例与失败判据**：与冷启动对照无计账差异（疑似重算）；已结算工作被重复结算；引用链断裂；只有"输出看似合理"而无 E4.1/E4.4 读数 → **判失败（红线 2）**。

**与前后阶段的因果关联**：续推结算经 put 回到 IS——闭环多跳成立；本阶段工件即公开复刻链的核心交付物。

## 4. 两条验收红线的操作化

| 红线 | 操作化 | 一票否决条件 |
|---|---|---|
| 不能以模型卸载日志代替旧 KV 不可达的证据 | O2.1 权威不可达 + O2.2a/b 双读数（O2.2b 覆盖阶段 3 恢复与阶段 4 续推） + O2.3 分级读数 + checkpoint 陷阱条款 | 缺任一判据，或观测到阶段 3/4 消费旧 KV/checkpoint → 阶段 2 失败 |
| 不能以恢复后输出看似合理代替已结算工作没有重新执行的证据 | E4.1 执行决策计账（主）+ token 辅助对照 + E4.4 分级派生绑定 | 无读数只有叙述，或对照显示重算，或把消费关系冒充值派生关系 → 阶段 4 失败 |

## 6. 公开复刻链要求（真机成功后）
