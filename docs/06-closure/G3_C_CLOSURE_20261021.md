## 3. 三项保留限制（binding）

**R1 — release 竞争不等于并发安全。** 原生对象析构探针、原子 continuation claim 与取消复检各自证明不同性质。executor 与 session 仍假定每臂一个串行驱动；release 与 step 竞争只保证 fail-closed（终止后不再提交），不构成通用线程安全。该假设是 D1 的前置条件，不是已实现的能力。

**R2 — `consumeBinding` → `duringGenerationRegistration` 存在不可回滚窗口。** gated 路径在 `continueExecutionG3WithPerArmCache` 内调用 `backend.consumeBinding(for:)`；返回后 `continueExecutionG3` 才调用 `duringGenerationRegistration`。注册失败会 fail-closed（不结算、不可再运行），但已消费的 ES 绑定不能撤销。这是提交顺序风险，不能由生命周期测试消除。

**R3 — 对象析构不代表物理内存归还。** 弱探针证明 cache、gateway、observer 的对象图在 release 后不可达并析构；它不证明 MLX 分配器已把 GPU/Metal 页归还操作系统。MLX 将 `cacheMemory` 描述为“未使用但保留在 buffer pool 中”的内存；C 未测量峰值占用或释放后的实际占用。
