# 入站转录归一化（Inbound Transcript Normalization）立项提案

状态：**DRAFT — 待批**
日期：2026-10-16
证据来源：2026-10-16 生产日志（会话 f21a38/main，13:31–15:17）
关联：`BRANCH_FORK_PROTOCOL_DRAFT.md`、prefixDiff 诊断（2026-10-15 首次生产命中）、toolEchoNormalize（v2.1.10, aad41a7）

## 1. 问题陈述

GDN 层不可回卷：入站转录与已缓存前缀在任意位置分叉后，分叉点之后的全部
token 必须重渲。当客户端在轮间改写转录（子代理段替换为摘要、工具回声格
式漂移）或两条转录共用会话键交替进场时，每一轮都触发全量级重渲。

2026-10-16 实测账单（单会话、83 分钟）：

| 时段 | 现象 | 重渲 token |
|---|---|---|
| 13:49–14:05 | 三轮 restore 全量重渲（分叉点=消息 8） | ~91.6K |
| 14:16–15:15 | 分叉税把轮长推出客户端 300s 窗口 → 11 笔超时报废 | ~370K 无效渲染 |

prefixDiff 诊断行现场抓到的分叉点：

```
index=8 stored(len=12479)='You are now acting as th…'
        incoming(len=1284)='状态已对齐：B3 仍是候选实现…'  commonPrefix=0
```

## 2. 现有缓解与其边界

- **prefix pool 多血统快照**（已在生产）：分叉后回退到正确血统的旧快照，
  今日把两笔 fork 点从消息 8 推迟到消息 10——有效但不完备，分叉点之后的
  内容仍全额重付。
- **toolEchoNormalize**（v2.1.10）：只治工具回声一种分叉源。
- **会话键系统提示指纹**（session-client-split）：治不同系统提示的客户端
  互踩；对同指纹的两条转录（主会话 vs 子代理）无效——今日 fp=true 仍分叉。

## 3. 候选设计（按侵入度排序，均未实施）

**A. 会话键加转录级判别维度（键层）**
最早稳定消息（如 messages[1..4]）的内容指纹并入会话表键。两条血统自然
分成两个缓存槽，交替进场不再互踢。
- 优点：键层窄改，pool/账本/checkpoint 血统机制全部自然继承。
- 风险：客户端合法的消息级早期编辑（如标题改写）会裂出新槽——需限制
  指纹取「不可变前缀」并设裂槽回收；血统跨重启语义需对齐既有 checkpoint 键。

**B. 分叉点最大前缀锚定（复用层）**
prefixMismatch 时不再以「最新 commit」为对照，而是按入站转录逐消息指纹
在血统池中选最长可匹配锚点再 fork（今日 pool 已做了近似版，提案为升格
为规范路径 + 全血统索引）。
- 优点：不改键、不改协议，纯复用策略优化。
- 风险：池规模与查锚成本；对「改写点之前也变了」的转录无解。

**C. 客户端契约文档化（规范层）**
在 README_base 增补铁律：客户端不得改写已提交消息（append-only 契约），
子代理会话须使用独立 session id。SimiGo 侧配套：改写型分叉打
`transcriptRewrite` 遥测标签（可证明事实，不估算）。
- 优点：零行为风险，把「每次改写=每轮全量重渲」的代价显式化。
- 风险：不约束第三方客户端（zcode-cli 现状即违反）。

**建议组合**：C 立即做（文档+遥测标签）；A 做小规模实验（探针会话验证裂
槽率）；B 视 A 的实验数据决定。

## 4. 验收口径

- 改写型分叉的每轮重渲 token 下降可从 trace 量化（promptTokens/mode 分布）；
- 暖窗口 extend 命中率（cacheEff ≥0.86 基线，2026-10-16 暖窗口实测
  0.79–1.00）不被新键策略拖低；
- prefixDiff/poolHit/reuseMiss 语义不回退（三层分离：Backend observation
  ≠ Runtime governance ≠ Tool execution）。

## 5. 明确不做

- 不引入 KV 树/并行分支/搬 llama.cpp（V1.5 方向定案红线）；
- 不动 prefill 选档（RuntimeTuning.swift:132-157 三轮实验已钉死）；
- 不预估、不伪造遥测（遥测语义诚实红线）。
