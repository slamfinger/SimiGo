## 4. 审计发现

### F-2（见证强度——J5 限定读法）

J5 的 durable-write 见证是**条目计数级**（branch-checkpoints
204→204、prefix-pool 2→2）。事后文件系统审计：

```text
branch-checkpoints：全天零文件修改（内容级干净——计数结论获内容级
                    佐证；204 文件平铺，见证真实）
prefix-pool：条目计数恒定，但条目 44eaa202… 内部 shard 在运行窗口
             被写入——P4 复制窗口 8 个（15:06/15:08/15:09）；
             原 P4 执行（11:43）与 P5 attempt 窗口（13:15/13:42）
             有一模一样行为 = 常态 runtime pool-export 行为，
             计数不可见；shard 为小增量（4–38 token 级；S₀ KV 为
             31712/1425 positions——基点 KV 从未以此形态导出）
```

污染后果评估：无可观察跨支效应——J4 换序逐字 8/8（可读通道必然
破坏恒等）、跨日输出逐位相同、全部 restore 由 ID-1 绑定 fixture
字节。**判定：J5 按注册操作化（计数级）PASS 维持；「零 durable
写入」措辞限定为：checkpoint store 内容级零写入已证；pool 存在
计数不可见的常态 runtime 导出（原跑同样存在），无可观察分支读效应。**

### F-3（仪器勘误——涉 P5-1 记录，不涉 P4）

G-α 审计中发现：P5-1 复制 harness 的 dirSHA256 内容见证对 pool 是
**深度 1**——对目录本身哈希得到常量 READ_ERR 串，故 P5-1 结果文档
§3 所称 pool「内容 SHA 见证」实际**空转**（checkpoint 目录见证为
真：平铺文件）。已在 P5-1 结果文档登记勘误。P5-1 判定不受影响：
其对照是 cacheEff 可观测量（baseline 0.977 vs treatment 0.000），
treatment 输出与原 attempt-1 逐字同形，窗口内 pool 写入即 F-2 所述
常态导出。
