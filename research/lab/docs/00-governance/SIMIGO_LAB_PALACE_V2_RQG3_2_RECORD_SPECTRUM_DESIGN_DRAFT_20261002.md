## 1. 核心问题（human 措辞，冻结）

> **不同程度的工作记录，在多大程度上既能支持继续工作，又能让
> 过去的判断重新被审查？**

## 2. 研究对象声明（human 措辞，冻结）

```text
不是「记录格式比较」（软件设计题）
而是：历史工作在未来是否仍然具有
      可恢复 · 可质询 · 可修正性
```

方法 = 同一个已经完成的真实工作（G1/G2 至 G2 T-3 停止点）
→ 人为只保留不同程度的历史记录 → 第二次重新面对同一工作
→ 分别观察四问：

```text
① 能否继续？
② 能否知道当时为什么这么做？
③ 能否发现当时判断可能有问题？
④ 能否定位需要重新检查的原始信息？
```

## 3. 两个真实故障锚点（非凭空设计，从已发生故障反推）

```text
案例 A（E6 V-5）：记录 D-rec-3 截断缺陷 vs 现实 F9/F10 公式
  测试 = 能否重新审查「过去记录本身」
案例 B（G3-1 E-X1）：历史排除「相邻主题」vs 0307/0308 内容证据
  测试 = 能否重新审查「过去的判断」
```

## 4. 记录谱系四档（从实际产物机械派生，零新整理）

```text
Tier-4 原样记录   = G1/G2 实际产物原样全量
                  （baseline-inventory.json / discovery-set.json
                  + corrections / t1-mapping-results.json /
                  G1·OQ-B·E6·G2 观察记录文档）
Tier-3 结构化记录 = 仅三份 JSON（baseline-inventory /
                  discovery-set+corrections / t1-mapping-results）
                  ——剥离叙事文档
Tier-2 结论摘要   = G2 T-3 综合产物 S1..S8 原文 + 关键判定行
                  （从 G2 执行记录逐字摘出，不加写）
Tier-1 当前位置   = 台账一行：「G2 T-3 完成；下一步 = RQ-G2-2
                  313,356万 来源追踪」
派生纪律 = 每档为上一档的机械子集/逐字摘录，禁止重新组织
          语言（防「漂亮摘要」污染——G3 设计裁定延续）
```

## 5. 重进任务（每档执行同一组）

```text
任务 α（继续性）：执行 RQ-G2-2 ——追寻 313,356万 完工总收入
                  的生产来源（在 Corpus-1 范围内可达的部分）
任务 β（可审查 A）：对照 D-rec-3 记录与 L0 现实（F9/F10 公式）
                  ——能否发现 V-5 截断缺陷？
任务 γ（可审查 B）：对照历史排除标记与 0307/0308 内容证据
                  ——能否发现 E-X1 原排除可能有问题？
（每档限用：该档记录 + L0 文件；禁止使用其他档/执行者记忆
  补充——执行者知识污染如实声明并记录规避方式）
```

## 6. 观察计量（每档 × 四问 + 重做量）

```text
① 能否继续     任务 α 推进程度 + 步骤/读取计数
② 知道为什么    任务 β/γ 中「当时为什么」可回溯的判定条数
③ 发现可能有问题 截断缺陷/E-X1 挑战在各档下能否被检出
④ 定位重检原始信息 需回 L0 的位置可否被指出
重做量         各档为完成任务 αβγ 需新增的读取/判断计数
```

「高/低」不在设计阶段预设——实验产出。

## 7. Evidence Grade 与判读纪律

```text
Observation = 每档任务 αβγ 的过程与结果（原样）
Inference   = 「N 级记录足以/不足以 X」级结论须跨档对照+
              替代解释排除；单档失败 ⇏ 该档无用（可能任务
              本身超纲）
Open        = 记录缺陷 vs 世界变化区分（纪律延续）
禁止比较「哪个格式最好」；禁止把谱系变成产品 API/存储设计
```
