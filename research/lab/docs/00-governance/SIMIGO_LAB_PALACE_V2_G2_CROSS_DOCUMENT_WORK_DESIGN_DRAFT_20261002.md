## 1. Research Question（低于抽象层，冻结）

> **一个正在进行的跨文件工作，如何持续利用已经发现的信息，并继续
> 向下一步推进？**

Corpus-1 操作化：

> 在 A（Excel 预算/成本）+ D（Word 汇报）已发现信息的基础上，
> 跨文件分析 / 对比 / 汇总工作能否持续进行并产生下一步推进？
> 已有发现能否真正成为下一次工作的起点？

## 2. Non-goals 与术语纪律（human 四要点冻结）

```text
❌ 不预设 Information Object / Relation / 知识图谱 /
   Provenance Schema / PALACE State Schema
❌ RQ-P3 数字口径映射 = 探针（逼出真实问题），不是答案
   （不提前定义「映射关系」）
❌ 不把 G1/E6 已发现事实升级为 PALACE 架构
❌ 不称「知识库」
```

## 4. 探针任务（三个，均跨文件，工作过程全记录）

### T-1 数字口径映射（RQ-P3 探针）

```text
任务陈述：「A 族汇总表数字与 D 族汇报数字之间存在什么对应关系？
          哪些能对上、哪些对不上、哪些无法判断？」
已登记数字清单（两侧，执行时全量落盘）：
  A 侧样本：合同收入 810,115,387.77 / 948,491,027.32；
            成本 708,802,383.39 / 694,263,135.39
  D 侧样本：完工总收入 313,356万；支出 251,029万；
            盈利 62,327万（+787万）；降本 2,071.69万；
            创收 8788.34万 / 9796万 / 7060万 / 1288万
判定口径（预登记）：能建立「数值相等 / 换算相等（万↔元）/
口径包含」任一关系 ⇒ 记为「已映射」；不能 ⇒ 记为
「未映射」并记录阻碍（口径？单位？范围？时点？）
```

### T-2 跨文件事实对照（钢筋线索）

```text
任务陈述：「钢筋价格在 A 族与 D 族中分别出现在哪里、数值是否
          一致、口径是否相同？」
已知线索（G1 登记）：D 侧「中标单价 4200 元/t」（汇报+pptx
  Slide 8）；A 侧附表1 钢筋公式 =4250/1.13/1000（折算 ≈ 3761
  ≠ 4200——数值差异候选，待实测核对）
```

### T-3 汇总任务（第 3 层首次进入）

```text
任务陈述：「综合 A+D 全部已发现信息，形成成本控制现状的一段
          综合陈述，并标注每个陈述点的来源文件。」
观察：综合过程中哪些步骤需要跨文件对照？哪些已有发现被
直接复用？哪些必须重新读取？综合产物与源文件的对应粒度？
```

## 5. 工作过程记录协议（human 要点 3，全任务适用）

```text
每步记录七元组：发现 → 选择依据 → 跨文件读取 → 对照 →
  冲突/对应 → 中间判断 → 下一步
依赖标注（每步必填）：本步是否使用了「前步已发现且当前输入
  未重新提供」的信息？（是 ⇒ 记录依赖哪条发现——H-G1-02 材料）
失败/不确定原样记录（不修饰）
```

## 6. 观察格

```text
OB-A 已发现信息复用  前步发现是否成为后步起点（H-G1-01 延续；
                     含「不再重读即可定位」的实例登记）
OB-B 映射可行性      T-1 的已映射/未映射分布与阻碍分类
                     （事实级；不抽象成映射模型）
OB-C 状态依赖        T-1..T-3 的工作链中 query-state dependency
                     步骤清单（H-G1-02 材料；两结果均有效）
OB-D 综合行为        T-3 综合产物的来源对应粒度与缺口
```

## 7. Evidence Grade 与判读纪律

```text
Observation = 工作过程记录 + 映射结果 + 综合产物
Inference   = 「PALACE 需要 X」级结论须替代解释排除
Open        = 无法建立对应/无法判定的条目（原样登记）
纪律：OB-B 出现漂亮映射结果也不得宣布「信息关系模型成立」；
      Gap 只登记不抽象
```
