# P4-A STEP①：Continuation Requirement 对抗性研究

日期：2026-09-22
状态：概念研究 / STEP① 审查
RQ：未分配
实验：未授权

## 1. 本轮攻击目标

上一轮将研究对象收缩为：

> 一个可明确描述的计算架构差异，在给定计算上下文下，对“继续计算所需信息”的依赖关系造成的可区分变化。

本轮不接受“Continuation Requirement”这个词本身作为定义，继续寻找其循环定义、不可观测性和最小反例。

## 2. 第一攻击：‘必须保留’是否只是实现选择？

反例：同一历史信息 H 可能有两种实现：

- 直接保存 H 的某种表示；
- 丢弃 H，之后重新计算 H。

因此：

‘被保存’ ≠ ‘继续计算所需’。

这排除了从内存对象、缓存对象或框架 buffer 直接反推出 Continuation Requirement 的路径。

## 3. 第二攻击：能否不用讨论‘知识’，直接定义所需信息？

可以暂时转向一个更严格的计算语义：

> 如果从两个不同的当前状态继续执行，在允许的相同未来输入/操作下，未来可区分行为可能不同，则两者不能被视为对继续执行完全等价的状态。

反过来，如果两个当前状态在研究范围内对所有允许的未来延续都不可区分，则对于该研究范围，它们可以视为 continuation-equivalent。

这给出了一个不依赖模型知识类别的候选关系：

Current State A ≈continuation Current State B

其判据来自未来延续行为，而不是来自 State 的物理长相。

## 4. 第三攻击：这是否又变成了‘输出等价’？

这是当前最危险的退化。

如果只比较最终 token / 最终输出，可能出现：

- 内部状态不同，但当前任务恰好输出相同；
- 不同计算路径在当前样本上碰巧收敛到相同结果。

因此‘单次输出相同’不能定义 continuation equivalence。

更强的候选是：

> 在限定的未来延续集合内，状态对继续计算的可区分行为保持等价。

也就是说，研究对象是‘对未来延续的响应能力’，而不是某一个输出。

## 5. 第四攻击：‘所有未来延续’不可实验枚举

严格的全量定义不可直接实验化。

因此必须区分三个层次：

1. 语义定义：研究范围内的 admissible continuation；
2. 有限测试集：实际选取的 continuation probes；
3. 经验结论：仅对被测试范围成立。

不能从有限 probes 推出数学意义上的所有未来延续等价。

这意味着未来若进入实验，必须把 probe space / workload scope 作为 estimand 的一部分，而不是隐藏在实验设置里。

## 6. 第五攻击：随机性、外部环境和副作用

如果计算包含随机数、时间、外部资源、网络、文件或其他环境状态，那么未来行为不仅由模型内部 State 决定。

因此更严格地说：

Continuation Requirement = 在给定计算环境与允许外部输入条件下，为保持目标计算延续语义所需的信息。

这进一步说明 Execution State 不能等同于‘模型内部 tensor 集合’。

## 7. 第六攻击：是否存在‘可重算但仍值得保存’的 State？

存在。

一个状态可以不是逻辑上不可替代的信息，却具有巨大的重算代价。

因此必须分开：

- semantic necessity：没有它是否无法按目标语义继续；
- computational value：保存它是否避免昂贵重算；
- resource value：保存它是否值得占用资源。

这三个概念不能合并。

特别重要的是：

> Execution State 的语义存在性，不以‘必须物理保存’为条件。

它可以是 reconstructable 的，只是其保存与否成为 Runtime 的资源决策。

## 8. 第七攻击：Continuation Requirement 是否已经足够表达 Architecture 差异？

目前可以看到一个更干净的关系：

Architecture Feature
→ 改变 Computation Dependency
→ 改变未来延续所需的信息关系
→ 改变可等价/不可等价的 State 类别

因此 P4-A 暂时不需要先找到一个具体‘State object’。

真正需要观察的是：

> 架构差异是否改变了当前状态对于未来延续的区分能力。

这比‘找缓存’或‘找 tensor’更接近研究对象本身。

## 9. 当前得到的最小语义框架

定义一个受限的 continuation probe 集合 C。

对当前状态 s，考虑在相同环境约束下应用 c ∈ C 后的可观察行为：

Behavior(s, c)

如果两个状态 s1、s2 对 C 内全部 probe 都不可区分，则暂记为：

s1 ≈C s2

如果存在某个 probe c，使：

Behavior(s1, c) ≠ Behavior(s2, c)

则它们在 C 范围内不可等价。

注意：这只是研究定义候选，不是已经验证的实验结论。

## 10. 这个框架对 P4 的意义

它把研究对象从：

‘Runtime 里有什么对象？’

转成：

‘当前计算状态对未来延续具有什么不可替代的区分能力？’

于是：

Physical Representation → Observable Proxy
而不是：

Physical Representation → Definition

这为跨模型比较保留空间：不同模型可以使用完全不同的物理 State，只要它们表现出可比较的 continuation semantics。

## 11. 当前最强反例仍然存在

即使这个语义框架成立，也不能推出：

- 存在唯一的最小物理 State；
- 存在唯一的 Runtime 管理对象；
- continuation-equivalence 一定对应明显的资源差异；
- 有限 probe 可以证明全空间等价；
- 架构差异一定导致 continuation semantics 差异。

因此研究仍然可以很快被关闭。

## 12. 本轮判断

当前没有找到足以关闭 P4-A 的反例。

但发现了一个关键收缩：

> **Continuation Requirement 最好不定义为‘必须保存的东西’，而定义为‘为了保持限定范围内未来延续语义，需要能够区分的信息关系’。**

这样可以自然区分：

语义必要性 ≠ 物理保存
语义必要性 ≠ 重算成本
语义必要性 ≠ 资源价值
输出相同 ≠ continuation-equivalent
观察到对象 ≠ 研究对象本体

## 13. 下一步

仍然不进入实验。

下一轮应攻击这个新框架最核心的地方：

> **有限 continuation probes 能否形成具有信息价值的最小判别集？**

如果不存在足够小、可重复、与架构差异相关的 probe 集合，那么当前语义抽象可能虽然理论上成立，却不具备可研究性；这将成为 P4-A 的真实关闭条件之一。
