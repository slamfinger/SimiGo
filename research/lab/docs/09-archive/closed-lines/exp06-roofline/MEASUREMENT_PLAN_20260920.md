# 实验 06 测量计划 — 256K Prefill Roofline 对账(预注册版)

**性质**:exp06 开工文档。判据以报告 §5.2 为准(≤1.5× 关 A / ≥3× 开 A /
中间逐算子归因),本文只登记公式、参数、测量清单与一个公式补项,
**全部在首份数据产生前预注册,防事后挑公式。**

## 2. 公式集(含补项)

**理论地板 = 各项字节搬运量之和 ÷ B_peak**,逐项:

1. **attention K/V 重读**(报告已钉死):causal 下 ≈
   `layers_attn × 2 × kv_heads × head_dim × bytes × Σ_chunks(o_i)`
   (chunk c 起始偏移 o_i;总量 ≈ n²/2 / c 项);
2. **权重重读(补项,本计划新增)**:chunked prefill 每 chunk 全量重读权重
   (20GiB 不入任何 cache):`n / c × W_bytes`。**小 chunk 下此项
   占主导**(例:n=120K, c=512:K/V 项 ≈338GB vs 权重项 ≈4.7TB,差一个
   量级)。忽略此项会把地板抬高一个数量级,把"贴顶"误判成"有 kernel
   opportunity"——这是补项必须预注册的原因;
3. **QK^T/O 矩阵乘字节**、embedding/lm_head、GDN 层线性读:逐算子归因
   阶段再细化。

**先行心算(仅判量级,非结论)**:n=120K, c=512,只计 1+2 项
≈ 5TB ÷ 153GB/s ≈ **33s 地板** vs 本机基线待测。若本机实测同生产机
量级(~600s+),比值 ≈ 20× → 直接落入"≥3× 开 A"区;**但必须先本机
重测基线**。同时注意:地板(512) > 地板(1024)(权重项 2×),而
实测(512) < 实测(1024)——交叉点即"内存压力劣化"的定量证据,
这是三档机制复核的判定形状。

| # | 测什么 | 工具 | 产出 |

## 4. 执行顺序与止损

1. 参数实读校准(模型 config)→ 2. M1(本机基线,无它不比)→ 3. M2+M3
   同场采集 → 4. 对账出比值 → 5. 判据区落定(报告 §5.2);中间地带
   → M5 + 逐算子归因后再判。
2. M1 若三档全部因 32GB 内存放不下 256K+35B 而不可跑,**记录并降深到
   可跑最大深度**(如 128K),公式不变、n 替换——不硬凑 256K 触发 swap
   污染数据。

## 5. 与 F1 的衔接

F1(E1 组)已实证单层稳态 update+eval 每步 O(depth)(1.6/4.7/20.7ms
@16K/65K/131K,线性)——若 M5 证实真模型 decode 同机制,decode 带宽
存在 ~2× 读放大,该放大同时是:exp06 比值的贡献项、Track A 的潜在
kernel opportunity、Track B F2 视图缓存/分页直读的收益来源。一处测量,
三处消费。
