## 2. G1.0 — what the repository actually contains

Read-only finding, recorded in full in `../SWIFT_CALCULATOR_BRIDGE_SPIKE.md`:

- The repository has **no Swift `Calculator` type** and no `ReferenceEchoCalculator`.
- The only continuation entry points are model executors
  (`MLXPrefixRecomputeExecutor.continueExecution(_:nextInputTokens:maxTokens:)`,
  `ExecutionContinuityCoordinator.continueExecution(_:continuation:)`), which take an
  `ExecutionStateHandle` and tokens and return generated tokens — they cannot express
  the contract's `(item_id, payload, dependencies) -> {swift_value}` entry, its five
  error codes, or its "no side effects" rule.

Therefore G1 implements a **test-only Swift reference oracle**. No claim is made that
any pre-existing project Calculator was executed, because none was identified.

## 6. Non-claims (binding)

1. **No project Calculator equivalence.** No such Calculator exists in the repository
   (G1.0). G1 proves that a Swift implementation of the frozen contract is consistent
   with the Python oracle and with the Carrier path — nothing about the product.
2. **No G2 evidence.** G1 says nothing about KV-cache release, Information-Space
   restoration into a new Execution State, or real-model incremental continuation.
   Those remain unproven.
3. **No model-level claim.** No model was invoked in this gate. All arithmetic is the
   frozen integer oracle.
4. **No production authorization.** R27 STOP and the non-implementation status of the
   signer line are untouched by this gate.
