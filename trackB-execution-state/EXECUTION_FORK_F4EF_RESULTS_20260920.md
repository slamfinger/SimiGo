## F4-E:模型级长深度 × 多段 decode 税——**>1.10× 稳定超标,F3a 重新激活**

方法(按审核矩阵):每配置一次构链(叶 = S 段 COW,P 解冻续写补至
同深 = 1 段 fresh 对照,同内容);warm-up 6 步不入稳态;每 rep 24 步、
首 token 与稳态分开;P/叶交替运行、深度锁步;3 reps;逐 token 门。

| 配置 | 稳态税比(3 reps) | 均值 | 判定(阈值 1.10×) |
|---|---|---|---|
| D8K@S4 | 1.006/1.043/1.051 | **1.033×** | ✓ 通过 |
| D18K@S4 | 1.117/1.137/1.014 | **1.089×** | ✓ 边缘通过 |
| D32K@S4 | 1.253/1.040/1.119 | **1.137×** | **✗ 超标** |
| D64K@S4 | 1.425/1.185/1.158 | **1.256×** | **✗ 显著超标** |
| D18K@S2 | 1.066/1.160/1.247 | 1.158× | ✗ 超标(方差大,非单调,记噪声待复核) |
| D16K@S8 | 1.089/1.125/1.155 | 1.123× | ✗ 超标 |

- **token 门:6 配置 × 72/72 全对**——多段链在全部深度语义正确,
  税是纯性能问题,正确性不受影响;
- 首 token(去 warm 后第一步)差异更大:64K P 58.9ms vs S段 108.0ms
  (1.83×)——含视图首次物化缓存 miss;
- **深度轴单调上升与机制吻合**:每 token 成本 ≈ 权重读 W(常数,
  MoE 激活 ~2GB)+ attention KV 读 αD + concat 读写 2αD → 税比
  (W+3αD)/(W+2αD) 随 D 单调增;@64K 理论 ≈1.28 vs 实测 1.256——
  **机制归因成立:税 = concat 的 2×depth 字节/token 物化往返**,
  非冷启动、非 promoted 特有(F4-B 的 1.90× 上界与此一致);
- 段数轴非单调(S2@18K > S8@16K),方差大——段数效应弱于深度效应,
  待复核。

**判定(按审核规则第三档)**:长深度多段稳定 >1.10× → **启动视图
物化路径剖析(F5)**。对 256K 目标深度,此税无界增长,是真实工程
问题。

### F5 方向(物化路径剖析的候选,按预期收益排序)

1. **fork 后一次性段合并(reattach)**:多段视图物化回单缓冲,一次
   O(depth) 拷贝换后续零税。量级估算 @64K:合并 ≈ 2.6GB 拷贝
   ≈ 17–50ms 一次性;当前税 ≈ 4ms/token × 每段 — **decode 超过
   ~10–15 token 即回本**;长分支会话全线受益;
2. slack fork 路径(单活跃主干,零税,F2-E5 已证)作为产品形态补充;
3. 段级视图缓存(私有未变复用 concat 结果;decode 每步私有变,
   需只重建尾段——与 1 等价的惰性版);
4. custom attention 直读多段(免物化;#1849/#629 合流位,kernel 层)。

## F4-F:Discard 生命周期归因——**不可达页可复用(无泄漏);单点不降 = 图父引用保持(强证据)**

三概念:逻辑引用释放 ≠ MLX 图引用释放 ≠ 物理归还。

| 实验 | 结果 | 结论 |
|---|---|---|
| ① 复用测试(20 轮 fork+8MB 追加+丢弃) | active 漂移 **0 KiB** | **不可达私有页可复用,无累积无泄漏** |
| ② 持有已 eval 视图节点时丢弃 | 建树 +94.7MB → 丢弃回降 13.8MB | 视图不完全阻塞回收;部分缓冲被保持 |
| ③ 组合丢弃(丢 B → 丢 root → 全丢) | 丢 B 0KiB、丢 root 0KiB(A1 靠段表存活且正确 ✓)、**全丢 -53MB** | **单点不降、全丢可降** ——被丢弃子树的缓冲被"某处"持有,全链释放后整体归还 |

**归因结论**:F4-B 单点 0 下降与 F4-C 24MB 下降不矛盾——释放由
ARC 即时完成(①),但 MLX 惰性图中**已 eval 节点保持父引用**(②③
模式吻合),物理归还延迟到引用链全灭或缓冲被复用(① 证明可复用)。
Instruments 级确认仍留档,但**无泄漏已由 ①+60 轮零漂移(F4-B)双重
证实**;工程语义:Discard 保证"可复用",不保证"立即降 RSS 指针"。

## 决策

1. **F3a 正式重新激活**:F4-E 深度轴稳定超标(1.137/1.256×)。
   F5 第一优先 = 段合并(reattach)原型 + 模型级复测(同 F4-E 矩阵
   缩样);验收 = 合并后长深度税回 ≤1.05× 且 fork→合并总成本
   @64K < 100ms。
2. F4-F 关闭"泄漏"担忧(复用 0 漂移);Instruments 确认为可选深挖。
3. F4-D 骨架更新:§6 性能警告项替换为 F4-E 归因结论(税 = concat
   2×depth bytes/token,模型带宽预算吻合),§8 补给计划数据就绪度:
   F4-E + F4-F 后可提交 #629 follow-up。
4. 边界重申:全部代码仅在 `exp/execution-state-fork`。
