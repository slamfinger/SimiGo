# F4-D 上游素材骨架:事实材料(2026-09-20)

**性质**:对接 mlx-swift-lm **#629**(本方 RFC,open)/ mlx-lm #1849 的
**事实材料骨架**。遵守复盘纪律:**只陈述已归因事实,未闭合项显式
标注,不包装成最终方案或已解决问题**。等 F4-E 首轮结果后决定是否
作为 #629 follow-up 补给(一次性提交,避免碎片化)。
**代码真源**:`exp/execution-state-fork` 测试内原型(非生产 API)。

## 1. 段表(page table)v2 数据结构与不变量

```
COWForkKVCache:
  kSegments/vSegments: [(array: MLXArray, rows: Int)]   // 只读段表
  privateKeys/privateValues: MLXArray?                    // 可写私有尾(step-256 增长)
  forkDepth = Σ segment.rows(= fork 时刻父代 offset)
```

不变量(全部有测试背书):
- **I1 只读域**:子代对段表引用的缓冲只读逻辑行 `[0, rows)`;父代
  append-only 写入不回写历史行(E2 实证:散射写就地、行区间不相交
  即安全;增长拼接换新缓冲对象,旧缓冲冻结)。
- **I2 逻辑行单调**:offset 只增(trim 关闭,`isTrimmable=false`——
  GDN 混合架构下 rewind 本就不可行,F0 §2)。
- **I3 段表组合律**:COW→COW fork = 复制父段表 + 追加父私有尾段
  (rows = 父已用行);O(1)(0.019–0.061ms,40 层 ×2)。
- **I4 GDN 对偶**:MambaCache fork = 两状态槽引用传递(函数式更新,
  零拷贝双向隔离,E4);LMOutput.State 经 Swift 字典值语义天然 fork。

## 2. O(1) Fork 的实际边界

- 已测:单层 @32K 四叉 0.019ms;模型级 40 层 ×2 0.061ms;链深 16
  fork 0.040ms(∝ 段数,µs 级);深度 32K→128K 无退化(F4-A 72 格)。
- 边界:**fork 本身零拷贝;首次消费(attention 读)物化 O(全深)
  视图**——这是"fork 成本"与"消费成本"的分离,见 §6 警告。

## 3. Root 解冻续写语义(已验证路径)

fork 后父代继续写 rows ≥ forkDepth 是安全的(段表只读 [0,forkDepth)
+ 行区间不相交)。真模型双门 16/16+16/16(F4-B-model):
rollback→主干继续生成→再 fork 的**核心数据结构路径已验证**。
未覆盖:并发/异步执行、资源生命周期条件(收窄表述,2026-09-20 复盘)。

## 4. Promote / Rollback 引用语义

- Promote = O(1) 引用切换,零拷贝(0.0003ms,Δactive=0);旧主干
  缓冲作为历史驻留,由 Discard 负责回收——逻辑迁移与物理所有权分离。
- Rollback = 保留的历史 (caches, state) 上重叉,O(1)(0.0043ms);
  历史树逐元素不变(F4-B)。
- Restore(盘):页恢复 = 私有页 I/O + 段表重挂,共享驻留时**亚线性**
  (平坦度 1.22,E6);重放恢复 ∝ gap(检查点粒度杠杆)。

## 5. Restore Depth 测量范围(显式声明)

16K/24K/32K 三点 × 单层 × 3 段链,3 reps 内零方差;**复杂度主张
限于该区间**。128K/多级链的恢复曲线未测(F4-A 覆盖了 fork/记账,
未覆盖盘恢复)。

## 6. 已知性能警告与资源回收问题(如实标注,未闭合)

1. **单层多段 concat decode 税**:1.10–2.4×(F1/F4-B 显微镜口径);
   模型级 4.2K 单段 1.01×;**18.4K/4 段 1.54–1.90×(上界,混合冷启动
   等变量,未归因)**——F4-E(8/18/32/64K × 1/2/4/8 段,warm 后交替
   对照)进行中,结果出来前不构成结论。
2. **Discard 单点 active 不降**(F4-B 0.0MiB vs F4-C 24MiB):三概念
   区分(逻辑引用释放 ≠ MLX 图引用释放 ≠ 物理归还);F4-F 复用/组合
   丢弃归因进行中;**不可达页最终可复用**已有 60 轮零漂移旁证。
3. 视图物化是消费侧成本:首次 attention 读 O(全深) 拷贝(与
   KVCacheSimple 稳态行为同型,非本设计新增)。

## 7. 与上游讨论的接口语义差异

| 维度 | #629 提案语言 | 本原型 | #1849(mlx-lm) |
|---|---|---|---|
| 所有权单位 | 缓存条目分支标识 / 引用计数段 | 段表(粗粒度页=每 fork 点一段) | page allocation/refcount |
| fork 返回 | 独立逻辑句柄 fork() | COWForkKVCache 对象(= 句柄) | — |
| COW 粒度 | 后缀级 | 段级(私有尾整体) | 页级提案中 |
| 存储层 | 可替换(提案询问 native vs hooks) | 段表在 cache 类内,未抽象接口 | 上游可能落地 |
| 混合架构(GDN) | 未涉及 | MambaCache 引用 fork + state 值语义 | #980 显示 hybrid 失效 |

**表态边界**:本地原型段表 ≠ 官方 paged KV 能力;若 #1849 以 hooks
落地,本设计愿意成为其上的 execution-state 实现(真源报告 §5.1
边界收窄立场不变)。
