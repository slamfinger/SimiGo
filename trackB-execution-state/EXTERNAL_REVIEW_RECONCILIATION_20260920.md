## 三、采纳的方法论告诫(写入纪律)

1. **"内存变化不能直接证明 memcpy"**——Discard ⚠ 归因实验必须结合
   实现语义 + allocator 统计 + 底层观测(Instruments),不以相关性
   代因果。此条并入 F4 续项②的验收标准。
2. **"不把真正 COW KV 写成 2.0 确定性承诺"**——与本仓用语纪律一致
   ("原型假设成立 / 候选架构能力");真源报告无需改动。
3. **模拟层边界**:若未来接口无法表达,才引入显式标注的模拟存储层
   分离验证抽象与共享——当前不需要(段表即真共享)。

## 五、附:MLX 数组所有权五分类的实测落点

探讨稿五分类(A 引用 / B 惰性节点 / C 物化后共享 / D 独立 / E 写时
副本)——F1-E2 实测:**MLX Swift 数组 = A(引用共享)+ 就地散射写,
无 E(写时副本)**;`copy()` = B(惰性切片)→ 首物化落入 D(独立
存储,+1×KV)。**正因底层无 E,应用层段表 COW 才是必要设计**——
这回答了"为什么不能只靠 Swift/MLX 默认行为实现 Branching Execution
State",也是 #629 的立论基座。
